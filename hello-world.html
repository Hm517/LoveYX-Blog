个人博客开篇：用代码构建属于自己的数字花园

2026-07-10 生活
博客Astro

为什么要搭自己的博客

2026 年了，公众号、知乎、Notion、Medium 这些平台一个比一个成熟，说实话在上面写东西也挺方便。但我还是觉得，自己搭个博客这件事，有些东西是平台给不了的。

第一个就是 数据自主权。你在别人家平台上写的东西，哪天平台策略一改、说关就关，你的文章可能就没了。自己的博客不一样——域名是你的，GitHub 上那个仓库是你的，没有算法替你决定这篇文章值不值得被看到。

还有一个原因是 技术表达的自由度。我写东西经常要嵌代码块、数学公式，偶尔还想放个交互图表。大多数平台对代码高亮的支持只能说凑合，Mermaid 流程图和 LaTeX 公式就更别想了。在自己博客里，渲染管线我自己说了算。

为什么选 Astro

静态网站生成器太多了——Hugo、Gatsby、Next.js、Hexo 都有人用。我最后选了 Astro，主要被这几个地方戳中了：

  • Islands Architecture（群岛架构）：大部分内容纯静态 HTML，只有需要交互的地方才加载 JS。页面默认零 JS，打开就是秒开。
  • 多框架混用：同一个项目里 React、Vue、Svelte 组件可以各玩各的，互不影响。
  • Content Collections：Astro 的内容层做得真好。用 Zod schema 定义 frontmatter 结构，编辑器里能自动补全，构建时元数据格式错了直接报错。

随便举个例子，定义一篇文章的 frontmatter 类型就这么简单：

// src/content/config.ts
import { defineCollection, z } from 'astro:content';

const blogCollection = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),
    date: z.date(),
    category: z.string(),
    tags: z.array(z.string()),
    description: z.string(),
    cover: z.string().optional(),
  }),
});

export const collections = { blog: blogCollection };

这个博客会写什么

LoveYX Blog 的主题就是「技术、AI、生活和一些乱七八糟的想法」。我不打算只写技术文章——摄影技巧、读书笔记、去了哪儿玩了什么，都会往上放。一个博客就该是完整的自己，干嘛把自己圈死在单一话题里。

接下来要做的事情：

  • 把标签系统和分类导航做好
  • 接上 Giscus 评论，讨论都回到 GitHub 上
  • 配上 RSS 订阅，不用依赖任何平台推流
  • 性能继续优化，Lighthouse 分往 95+ 搞

就这些了

搭博客这件事本身就挺有意思的。每一行代码、每一处留白、选的每一个字体，都带着自己的痕迹。希望这个小花园慢慢长起来吧，路过的朋友也欢迎多来看看。
